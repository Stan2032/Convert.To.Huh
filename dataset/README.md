# Conversion Loss Registry

**What each file-format conversion destroys, measured rather than asserted.**

`conversion-loss-registry.json` — CC0-1.0, no attribution required.

## Why this exists

[PRONOM](https://www.nationalarchives.gov.uk/PRONOM/) tells you *what a file
is*: ~2,000 signatures, an API, used across the preservation world. Nothing
tells you **what converting it costs you**.

The digital preservation field discusses conversion loss constantly — resolution
lost, layers flattened, formatting dropped, precision truncated — as prose
guidance. This is an attempt to publish the same knowledge as data.

## Using it

```bash
curl -O https://raw.githubusercontent.com/Stan2032/Convert.To.Huh/main/dataset/conversion-loss-registry.json
```

```python
import json
d = json.load(open("conversion-loss-registry.json"))

# What does converting PNG to JPEG destroy?
for e in d["edges"]:
    if e["from"] == "image/png" and e["to"] == "image/jpeg":
        print(e["engine"], e["verification"], e["loss"])
# image-rs verified {'alpha': 'lost', 'color_depth': 'degraded', ...}
```

## The one thing you must not ignore

Every edge carries a `verification` field:

| Value | Meaning |
|---|---|
| `verified` | Run against a real specimen and measured. Trust it. |
| `claimed` | Asserted from documentation and **not tested**. Treat as a hint. |
| `refuted` | Tested and found not to work. |

**`claimed` entries are untested.** They are published because a documented
claim is still information, but they carry no measurement behind them. Filter on
`verification == "verified"` if you need reliability.

Current counts are in the `counts` object of the dataset itself.

### Check the evidence, don't just trust the label

A `verified` edge ships the measurement that earned the label, in `specimens`
and `measured`:

```json
"verification": "verified",
"specimens": ["corpus/audio/highfreq-mono.wav", "corpus/audio/stereo-distinct.wav"],
"measured": {
  "engine_build": "ffmpeg 6.1.1",
  "metric": "band energy retained vs the WAV original",
  "band_1khz_retained": 0.903,
  "band_15khz_retained": 0.902
}
```

`measured` is deliberately **not** a fixed shape. The metric depends on the
domain — SSIM for raster, band energy or SNR for audio — and forcing one schema
would either exclude domains or invent comparability that does not exist. Always
read `metric` before comparing two numbers; `engine_build` names the exact build
the claim rests on, which is not always the same as the engine's `version_pin`.

So `signal_fidelity: "degraded"` is a starting point, not the answer. Whether a
10% band-energy loss matters is your decision, and you can only make it with the
number in front of you.

## Structure

| Key | Contents |
|---|---|
| `properties` | The closed vocabulary of preservable properties, with definitions. Loss vectors are only comparable because this list is fixed. |
| `formats` | Format identity, extensions, MIME types, PRONOM PUID, and which properties the format *can* carry. |
| `engines` | The software that performs conversions, with version pins and licences. `build_profiles` says which distribution profiles may ship it (`lgpl` = safe in a proprietary product, `gpl` = self-host only); `spdx_components`, `patent_exposure` and `license_verified` are there so you can apply your own policy rather than inherit ours. **`license_verified: false` means nobody read the licence text** — treat the profile as a guess. |
| `edges` | One entry per `(engine, from, to)`. The same conversion through different engines is a **different edge**, because engines lose different things. |

Each edge's `loss` maps a property to `preserved`, `degraded`, `lost`, or
`synthesized`. An absent property is not applicable to that conversion.

`synthesized` means the property was **not present in the input** and was
generated by a model — OCR text, a speech transcript, a traced vector. It is a
different axis from loss: the content is an estimate, not a re-expression, and
must never be presented as if extracted.

## Scope, honestly

Small and raster-heavy. It grows by measurement, not assertion, which is slow on
purpose — two of the four errors this project's validator has caught were in
hand-written loss vectors that looked entirely reasonable.

Corrections and additions are welcome and easy to make: see
[`CONTRIBUTING.md`](../CONTRIBUTING.md). Contradicting a `verified` edge with a
measurement is the most valuable thing you can send.
